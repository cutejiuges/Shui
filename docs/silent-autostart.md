# 静默开机自启动

对应上游 [Issue #27](https://github.com/rock-zhang/Shui/issues/27)。

## 使用方式

在“通用”设置中开启“开机自启动”。下次登录系统时，Shui 会按已有提醒规则在后台计时，托盘继续显示状态，设置窗口保持隐藏且不抢焦点。到达提醒时间后，按已有设置显示全屏提醒或系统通知。

需要修改设置时，从托盘选择“偏好设置”。手动启动 Shui 也会显示设置；应用已在后台运行时，会打开现有实例的窗口。macOS 同时支持从 Finder 再次打开应用。窗口最小化时，手动打开会先恢复窗口。

关闭设置窗口后，应用继续在后台运行。再次触发静默启动会复用已有实例，并保持当前窗口状态；已手动打开的设置不会被隐藏。

开关读取操作系统的实际注册状态，切换期间暂时禁用；系统注册失败时保留原开关状态并提示重试。关闭开关后取消后续登录时的自动启动，当前进程继续运行。

## 启动行为

| 场景 | 设置窗口 | 托盘、计时和提醒 |
| --- | --- | --- |
| 系统登录，启动参数包含 `--silent` | 创建时即隐藏，不聚焦 | 正常运行 |
| 手动启动，不带 `--silent` | 显示并聚焦 | 正常运行 |
| 后台运行时再次手动启动 | 恢复并显示现有窗口 | 复用现有进程 |
| 已运行时再次静默启动 | 保持当前窗口状态 | 复用现有进程 |
| 从托盘打开偏好设置 | 恢复并显示现有窗口 | 正常运行 |

`--silent` 只控制本次启动时是否主动显示设置窗口。已有自启动注册使用的也是这个参数，升级后即可使用。自启动仍由系统管理，不会因为手动启动应用而自动开启。

主窗口初始隐藏配置同时覆盖 macOS、Windows 和 Linux。隐藏的主 WebView 仍加载设置页面和后台事件监听；macOS 14 及以上通过 [WebView 后台节流配置](https://v2.tauri.app/reference/config/#backgroundthrottling)保持提醒事件处理。单实例插件在其他插件之前注册，防止重复启动托盘和计时器。

## 验证

自动检查沿用仓库 CI：

```sh
node --test tests/*.test.cjs
corepack yarn eslint -c src/eslint.config.mjs src
corepack yarn build
cargo test --workspace --locked
```

Rust 回归测试覆盖手动启动、静默启动、无关参数、精确参数匹配、非 Unicode 参数，以及 Tauri 合并后的三平台窗口与托盘配置。

`tests/tray-settings.test.cjs` 使用真实托盘 hook 和模拟的原生 API 边界，验证“偏好设置”能够显示、聚焦隐藏窗口，恢复最小化窗口，并容忍窗口暂不可用。

### 三平台 CI 与原生启动冒烟

`.github/workflows/ci.yaml` 在 macOS、Windows Server 2022 和 Ubuntu 24.04 上分别执行 Rust 测试、默认应用构建和原生冒烟。前端构建产物由同一工作流共享。失败时保留各进程日志、原生状态、系统启动命令和 JSON 验证报告。

冒烟使用显式启用 `native-smoke` 的隔离构建，应用标识为 `com.shui.native-smoke`，名称为 `Shui Native Smoke`。该构建通过真实 Tauri 窗口 API 读取可见、聚焦和最小化状态；真实 WebView 在提醒监听注册及托盘菜单安装完成后回报就绪。测试调用实际注册的托盘设置回调，并启动第二个应用进程验证单实例行为。

测试还会注册系统自启动，读取 Windows 注册表、macOS plist 或 Linux `.desktop` 文件，再使用其中的原始启动命令冷启动应用。后台提醒通过已有计时器、隐藏 WebView、真实 IPC 和原生提醒窗口完成，测试结束后移除隔离启动项、停止进程并归档隔离数据。

默认构建不包含 Rust 观测器及测试控制入口；测试特性拒绝生产应用标识。测试无需 WebDriver，使用 Python 标准库驱动，因此同一套原生断言也可在 macOS 上运行。

macOS / Windows 本地执行：

```sh
corepack yarn build
python3 tests/native/startup_smoke.py --build --artifacts artifacts/native-smoke
```

Windows 也可以使用 `python`。Linux 安装 CI 中列出的依赖后执行：

```sh
dbus-run-session -- xvfb-run -a -s '-screen 0 1280x1024x24' \
  python3 tests/native/startup_smoke.py --build --window-manager openbox --artifacts artifacts/native-smoke
```

Linux CI 覆盖 X11 虚拟桌面。物理托盘点击、真实注销后重新登录，以及 KDE/GNOME Wayland 的焦点与托盘行为仍需要对应桌面会话验收。冒烟中的即时提醒验证调度链路；下面的首次本机验收另外覆盖了六分钟持续隐藏。

原生验收需要覆盖：

1. 在其他应用保持焦点时静默启动，确认无设置窗口闪现，原应用保持焦点。
2. 确认托盘菜单可用、倒计时推进；主窗口持续隐藏超过五分钟后仍能自动触发提醒。
3. 从托盘打开偏好设置，关闭后再次打开；最小化后也能恢复。
4. 普通启动显示设置，后台运行时再次普通启动复用原进程；再次静默启动保持当前窗口状态。
5. 开启自启动后检查系统启动项包含 `--silent`，使用该启动项验证后台启动；关闭后确认启动项移除。
6. 验证开关的加载、成功、失败及操作中禁用状态，失败后能够重试。

Windows 和 Linux 的桌面交互及真实系统登录需要分别在对应平台验收；三平台配置测试不能代替实机验证。
